## Backend (`origin/Backend` → carpeta `BACKEND/`)

### Resumen de lo hecho

Jornada centrada en dos cambios estructurales del módulo de Mantenimiento/Operaciones, más dos commits de documentación.

**Fix: vinculación de equipos solo en fase de ejecución** (`operaciones.py`, commit `19cfff26`)

- `actualizar_estado_servicio`: al hacer la transición `Pendiente → En_Proceso` se dispara la vinculación por primera vez, garantizando que suceda justo cuando el servicio comienza.

- `crear_servicio` ya no instancia procedimientos. `detalle_servicio` elimina la instanciación perezosa.
- `_procedimientos_de` del equipo devuelve solo histórico, sin crear copias.
- El campo `sin_procedimientos_estandar` se conserva en las respuestas con valor `false` por compatibilidad con Angular.

**Documentación** (commits `46535a03` y `e8f6ca15`)

### Hallazgos

**1. `setState` dentro de un bucle — rebuilds innecesarios**
- **Archivo:** `e_zyro_app/lib/screens/pantalla_camara_campo.dart`, línea **1065**
- **Contexto:** método `_AlmacenAsignadorState._subirTodas()` (clase interna del flujo "Almacén"):
  ```dart
  for (var i = 0; i < widget.fotos.length; i++) {
    final r = await widget.subir(widget.fotos[i].path, widget.pasos[a]);
    if (!mounted) return;
    setState(() => _resultado[i] = r);   // ← rebuild por cada foto
  }
  ```
- **Problema:** Se llama a `setState` en cada iteración del bucle, lo que provoca una reconstrucción completa del widget por cada foto subida. Con N fotos, hay N rebuilds donde podría haber uno solo al final.
- **Mejora sugerida:** Actualizar `_resultado[i]` directamente fuera del `setState`, y llamar a `setState(() {})` una única vez al salir del bucle (o mantener la actualización por item pero con un `ValueNotifier<List<bool?>>` para que solo reconstruya la fila afectada):
  ```dart
  for (var i = 0; i < widget.fotos.length; i++) {
    final r = await widget.subir(widget.fotos[i].path, widget.pasos[a]);
    if (!mounted) return;
    _resultado[i] = r;   // mutación directa
    if (r) ok++;
  }
  if (mounted) setState(() {});   // un solo rebuild al terminar
  ```
  *Nota: la diferencia es relevante principalmente si la lista tiene muchas fotos y el widget es costoso de reconstruir; con 1–3 fotos el impacto es mínimo.*
