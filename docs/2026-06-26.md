### Hallazgos

**1. `BACKEND/app/routers/rrhh_asistencia.py:748` — Filtro O(n×m) dentro del bucle por empleado**

En `_build_cronograma`, por cada empleado se itera `dias_all` (hasta 31 días) y por cada día se filtra la lista completa de registros de ese empleado:

```python
regs_dia = [r for r in regs if r.fecha_hora.date() == dia]
```

Para un informe mensual con 100 empleados promediando 40 registros/mes, esto son ~124 000 comparaciones. El mismo patrón se repite en otras dos funciones del mismo archivo (líneas 272 y 946).

**Sugerencia:** construir un `defaultdict(list)` indexado por `.fecha_hora.date()` una vez por empleado antes del bucle `for dia in dias_all`:

```python
regs_por_dia: dict[date, list] = {}
for r in regs:
    regs_por_dia.setdefault(r.fecha_hora.date(), []).append(r)
# ...
regs_dia = regs_por_dia.get(dia, [])
```

Esto reduce la búsqueda a O(1) por día.

**2. `BACKEND/app/models/usuario_permiso.py:21` — `datetime.utcnow` deprecado en Python 3.12+**

```python
created_at = Column(DateTime, default=datetime.utcnow, nullable=False)
```

`datetime.utcnow` es un método deprecado desde Python 3.12 (emite `DeprecationWarning`) y será eliminado en versiones futuras. El default correcto con zona horaria explícita es:

```python
from datetime import datetime, timezone
created_at = Column(DateTime, default=lambda: datetime.now(timezone.utc), nullable=False)
```

---

**3. `BACKEND/app/db/database.py` — `use_insertmanyvalues=False` enmascara un problema de esquema**

El workaround desactiva las inserciones en lote de SQLAlchemy 2.0 para evitar el crash por `str`/`UUID` en el sentinel. La causa raíz es que varios modelos declaran `String(36)` sobre columnas `uuid` nativas en PostgreSQL. El comportamiento correcto a largo plazo sería declarar las columnas como `UUID(as_uuid=True)` (o `UUID(as_uuid=False)` y normalizar el tipo en ambos lados), en vez de deshabilitar una optimización global. No es un bug operacional inmediato, pero acumula deuda técnica y hace que inserciones bulk sean más lentas en toda la aplicación.

---

**4. `BACKEND/app/routers/rrhh_asistencia.py` — `_hoja_perfil` recibe módulos de ReportLab como parámetros**

La función acepta `colors, Table, TableStyle, Paragraph, Spacer, ParagraphStyle, cm` como argumentos posicionales para evitar re-importar dentro de ella. Sin embargo, estos objetos son módulos/clases, no datos; la firma es frágil y dificulta la legibilidad. Lo más sencillo sería mover los imports de ReportLab al nivel de módulo (con `TYPE_CHECKING` si se quiere evitar el coste de importación en arranques sin PDF) o repetir el `from reportlab...` al inicio de la función.

### Hallazgos

**1. `e_zyro_app/lib/services/fcm_flutter_service.dart:119` — `refrescarPermisosGlobal()` sin `await` antes de navegar**

En `_onMessageOpenedApp` (handler de tap sobre notificación):

```dart
case 'perfil_actualizado':
    refrescarPermisosGlobal();                                  // ← sin await
    Navigator.of(ctx).pushNamedAndRemoveUntil('/', (_) => false);
```

La navegación ocurre antes de que los nuevos permisos se carguen en `AppSession`. La pantalla principal renderiza con los permisos viejos; si el refresco termina después, el notifier dispara un rebuild, pero hay una ventana donde el usuario ve accesos incorrectos (o faltantes). En el handler de primer plano (línea 89) el mismo llamado sí usa `await` correctamente.

**Sugerencia:** agregar `await` antes de navegar:

```dart
case 'perfil_actualizado':
    await refrescarPermisosGlobal();
    Navigator.of(ctx).pushNamedAndRemoveUntil('/', (_) => false);
```

**2. `e_zyro_app/lib/main.dart:407-409` — Sin debounce en `didChangeAppLifecycleState`**

```dart
void didChangeAppLifecycleState(AppLifecycleState state) {
    if (state == AppLifecycleState.resumed && isOnlineNotifier.value) {
        _refrescarSesionYNav();
    }
}
```

Cada transición `background → foreground` (incluso al bajar la barra de notificaciones o cambiar brevemente de app) dispara una llamada a `/auth/me` más posiblemente una redirección de pantalla. En dispositivos con conexión inestable o en contextos de múltiples cambios rápidos, el usuario puede ver flashes de navegación o estados de carga repetidos.

**Sugerencia:** guardar el timestamp del último refresco y saltarlo si fue hace menos de 60 segundos:

```dart
DateTime? _lastRefresh;

void didChangeAppLifecycleState(AppLifecycleState state) {
    if (state == AppLifecycleState.resumed && isOnlineNotifier.value) {
        final now = DateTime.now();
        if (_lastRefresh == null || now.difference(_lastRefresh!).inSeconds > 60) {
            _lastRefresh = now;
            _refrescarSesionYNav();
        }
    }
}
```
