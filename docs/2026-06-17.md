### Hallazgos

#### 1. N+1 queries al listar carpetas del Drive
**Archivo:** `BACKEND/app/routers/drive.py` — función `_carpeta_out` (llamada desde `listar_carpetas`)

Por cada carpeta devuelta, `_carpeta_out` lanza dos `COUNT` adicionales a la BD (subcarpetas e hijos). Con N carpetas en un directorio se ejecutan 2N+1 consultas en lugar de 1.

```python
# Situación actual: 2 queries por carpeta
def _carpeta_out(db, c):
    subc = db.query(func.count(DriveCarpeta.id)).filter(DriveCarpeta.padre_id == c.id).scalar()
    narch = db.query(func.count(DriveArchivo.id)).filter(DriveArchivo.carpeta_id == c.id).scalar()
    ...
```

**Mejora sugerida:** Cargar los conteos en un único query con `GROUP BY` antes de iterar, o usar subconsultas correlacionadas en el SELECT principal, eliminando la N+1.

#### 2. Archivo huérfano en Cloudinary si falla el commit
**Archivo:** `BACKEND/app/routers/drive.py` — función `subir_archivo` (líneas donde se llama a `subir_archivo_base64` antes de `db.commit()`)

El archivo se sube a Cloudinary antes de que la fila en BD se confirme. Si `db.commit()` lanza una excepción (constraint, timeout, etc.), el binario queda en Cloudinary sin registro en la BD y no hay mecanismo de limpieza.

**Mejora sugerida:** Envolver el commit en un `try/except` y, ante fallo, llamar a `eliminar_recurso_por_public_id` para revertir la subida.

```python
try:
    db.add(a)
    db.commit()
except Exception:
    eliminar_recurso_por_public_id(res["public_id"], resource_type=...)
    raise
```

#### 3. Subqueries correlacionadas por usuario en `_SELECT_USUARIO`
**Archivo:** `BACKEND/app/routers/usuarios.py` — constante `_SELECT_USUARIO`

Para cada fila de usuario se ejecutan dos subqueries correlacionadas (una con `string_agg` para el nombre del rol, otra con `LIMIT 1` para el `rol_id`). Con decenas de usuarios el impacto es menor, pero escala linealmente.

```sql
-- Dos subqueries correlacionadas por usuario:
(SELECT string_agg(r.nombre, ', ') FROM usuario_rol ur JOIN rol r ... WHERE ur.usuario_id = u.id) AS rol,
(SELECT r.id::text FROM usuario_rol ur JOIN rol r ... WHERE ur.usuario_id = u.id ORDER BY r.nombre LIMIT 1) AS rol_id,
```

**Mejora sugerida:** Reemplazar por un `LEFT JOIN LATERAL` o una CTE que agrupe `usuario_rol` una sola vez, reduciendo de 2N a 1 join total.

### Hallazgos

#### 1. `base64Encode` de archivos grandes en el hilo principal (UI thread)
**Archivo:** `e_zyro_app/lib/screens/pantalla_drive.dart` — función `_subirArchivo`

```dart
final base64 = base64Encode(bytes); // síncrono, puede bloquear hasta ~250 ms para 30 MB
```

`base64Encode` es síncrono y corre en el main isolate. Para archivos cercanos al límite de 30 MB (tamaño base64 ≈ 40 MB) puede congelar la interfaz varios cientos de milisegundos.

**Mejora sugerida:**
```dart
final base64 = await compute(base64Encode, bytes);
```

El mismo patrón aplica en `pantalla_editar_perfil.dart` (foto de perfil), aunque el impacto es menor por la compresión previa a 1024×1024.

#### 2. Error silencioso cuando falla `listarArchivos`
**Archivo:** `e_zyro_app/lib/screens/pantalla_drive.dart` — función `_cargar`

if (cs.ok) {

#### 3. Llamadas API secuenciales e independientes en la pantalla de gestión de usuarios
**Archivo:** `e_zyro_app/lib/screens/pantalla_gestion_usuarios.dart` — función `_cargar`

```dart
final us = await _svc!.listar();   // espera a terminar antes de lanzar la siguiente
final rs = await _svc!.roles();    // podría ejecutarse en paralelo
```

Ambas llamadas son completamente independientes; ejecutarlas en serie duplica el tiempo de carga de la pantalla.

**Mejora sugerida:**
```dart
final results = await Future.wait([_svc!.listar(), _svc!.roles()]);
final us = results[0] as ApiResult<List<UsuarioAdmin>>;
final rs = results[1] as ApiResult<List<RolItem>>;
```

#### 4. Loop secuencial para agregar ítems al borrador de préstamos
**Archivo:** `e_zyro_app/lib/screens/pantalla_prestamos_servicio.dart` — función `_enviar` en `_SolicitarPrestamoSheetState`

```dart
for (final e in _carrito.entries) {
  if (await widget.service.agregarItemBorrador(widget.servicioId, e.key, e.value)) {
    ok++;
  }
}
```

Cada ítem del carrito se envía con un `await` secuencial. Con N equipos seleccionados, el tiempo de espera escala linealmente con la latencia de red.

**Mejora sugerida:** Lanzar todas las solicitudes en paralelo y contar los éxitos:
```dart
final resultados = await Future.wait(
  _carrito.entries.map((e) =>
    widget.service.agregarItemBorrador(widget.servicioId, e.key, e.value)),
);
final ok = resultados.where((r) => r).length;
```
