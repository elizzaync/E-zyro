### Hallazgos

**1. `BACKEND/app/core/session_cache.py` — `_activo_cache` sin límite de tamaño**

El nuevo diccionario `_activo_cache` (añadido en `175bf8e0`) no tiene control de tamaño. El diccionario `_cache` ya existente usa `_MAX_ENTRADAS = 10_000` con la función `_podar()`, pero `_activo_cache` carece de cualquier mecanismo equivalente. En despliegues de larga duración con muchos usuarios distintos, el dict crecerá indefinidamente en memoria.

_Mejora sugerida:_ Al inicio del bloque `with _activo_lock:` en la ruta de escritura, añadir la misma guarda que en `_podar()`:
```python
if len(_activo_cache) >= _MAX_ENTRADAS:
    _activo_cache.clear()
```

**2. `BACKEND/app/routers/usuarios.py` — Cache no se actualiza al *reactivar* una cuenta**

En `cambiar_activo()` (`175bf8e0`), `invalidar_activo(usuario_id)` sólo se llama cuando `body.activo == False`. Si un administrador reactiva una cuenta que estaba desactivada, la entrada `(False, expira_en)` permanece en `_activo_cache` hasta que expire el TTL (30 s), haciendo que el usuario reciba un `403 cuenta_desactivada` durante ese intervalo aunque su cuenta ya esté activa en BD.

_Mejora sugerida:_ Eliminar la condición y actualizar el cache en ambos sentidos:
```python
# en session_cache.py, renombrar/generalizar invalidar_activo:
def _set_activo_cache(usuario_id: str, activo: bool) -> None:
    with _activo_lock:
        _activo_cache[usuario_id] = (activo, time.monotonic() + _TTL_SEGUNDOS)

# en usuarios.py:
_set_activo_cache(usuario_id, body.activo)  # siempre, no sólo al desactivar
```

**3. `BACKEND/app/routers/evaluaciones.py` — `getattr(c, "pregunta", None)` enmascara deriva de esquema**

En `listar_criterios()` y `_plantilla_items_out()` (`f44fef99`) se usa `getattr(c, "pregunta", None)` en lugar de acceder directamente a `c.pregunta`. Como el campo ya está declarado en el modelo ORM (`evaluacion.py`), el `getattr` es innecesario y oculta posibles errores de esquema: si la migración no se hubiera aplicado, el acceso fallaría silenciosamente devolviendo `None` en lugar de un error detectable.

_Mejora sugerida:_ Acceder directamente a `c.pregunta` en ambas funciones. Si la columna existe en el modelo, SQLAlchemy la expondrá con ese nombre sin necesidad de `getattr`.

### Hallazgos

**1. `e_zyro_app/lib/screens/pantalla_evaluaciones.dart` y `pantalla_personal_hub.dart` — `getEvaluacionService()` recrea `ApiClient` en cada carga**

`getEvaluacionService()` (definido en `api_provider.dart`) llama `SharedPreferences.getInstance()` y construye un nuevo `EvaluacionService(ApiClient(prefs))` cada vez que se invoca. En `_EvaluacionesTabBodyState._cargar()` y en `_EvaluacionesEmpleadoTabState._cargar()` / `_asignarEvaluacion()`, esto ocurre en cada pull-to-refresh, cada vez que el usuario crea una evaluación y cada vez que se abre el diálogo de asignación. La llamada a `SharedPreferences.getInstance()` es una llamada de plataforma asíncrona que introduce latencia innecesaria.

_Mejora sugerida:_ Almacenar el servicio como campo de estado, inicializándolo una sola vez en `initState()`:
```dart
EvaluacionService? _svc;

@override
void initState() {
  super.initState();
  getEvaluacionService().then((s) { _svc = s; _cargar(); });
}

Future<void> _cargar() async {
  if (_svc == null) return;
  // usa _svc directamente
}
```

**2. `e_zyro_app/lib/screens/pantalla_mi_espacio.dart` — Filtros `asignadas`/`historial` recalculados en cada `build()`**

Dentro del método `build()` de `_MisEvaluacionesTabState` (líneas añadidas en este commit):
```dart
final asignadas = _items.where((e) => e.esAsignada).toList();
final historial = _items.where((e) => !e.esAsignada).toList();
```
Estas dos iteraciones O(n) sobre `_items` se ejecutan en cada reconstrucción del widget (scroll, actualización de estado padre, etc.). Para listas de evaluaciones pequeñas esto es irrelevante, pero es un patrón que se presta a regresiones si la lista crece.

_Mejora sugerida:_ Calcular y guardar ambas listas en `setState()` después de cargar los datos:
```dart
List<Evaluacion> _asignadas = [];
List<Evaluacion> _historial = [];

setState(() {
  _items = data;
  _asignadas = data.where((e) => e.esAsignada).toList();
  _historial = data.where((e) => !e.esAsignada).toList();
});
```

**3. `e_zyro_app/lib/screens/pantalla_personal_hub.dart` — `DateTime.now()` invocado dos veces en el mismo statement**

En `_asignarEvaluacion()`:
```dart
TextEditingController(
  text: '${DateTime.now().year}-S${DateTime.now().month <= 6 ? '1' : '2'}',
)
```
Se llama a `DateTime.now()` dos veces. Aunque en la práctica el resultado es idéntico, es un estilo descuidado que puede dar lugar a valores distintos justo en el cambio de segundo en año nuevo.

_Mejora sugerida:_
```dart
final now = DateTime.now();
TextEditingController(text: '${now.year}-S${now.month <= 6 ? '1' : '2'}')
```
