### Hallazgos

#### 1. Bug de aislamiento multi-tenant — `asistencia.py:1316`

**Archivo:** `BACKEND/app/routers/asistencia.py`, línea 1316  
**Commit:** `0b501010`

```python
con_turno = {
    str(te.empleado_id)
    for te in db.query(TurnoEmpleado).filter(TurnoEmpleado.activo == True).all()
}
```

La consulta carga **todos** los `TurnoEmpleado` activos de la base de datos sin filtrar por `empresa_id`. Esto provoca que empleados de otras empresas aparezcan como "ya tienen turno asignado", bloqueando su correcta asignación si coincide el `empleado_id`. En un entorno multi-tenant es un bug de correctitud y potencial fuga de datos.

**Corrección sugerida:** unir con `Empleado` y filtrar por empresa:

```python
con_turno = {
    str(te.empleado_id)
    for te in db.query(TurnoEmpleado)
        .join(Empleado, Empleado.id == TurnoEmpleado.empleado_id)
        .filter(
            Empleado.empresa_id == empresa_id,
            TurnoEmpleado.activo == True,
        ).all()
}
```

**Corrección sugerida:** eliminar `_TECNICO_TAGS` y reescribir `_limpiar_obs` para iterar sobre esta tupla, evitando la duplicación:

```python
_PIPE_TAGS    = (" | Hora entrada registrada:", " | Hora declarada:")
_PREFIX_TAGS  = ("Hora entrada registrada:", "Hora declarada:")

def _limpiar_obs(raw: str) -> str:
    if not raw:
        return ""
    for tag in _PIPE_TAGS:
        idx = raw.find(tag)
        if idx != -1:
            return raw[:idx].strip()
    if any(raw.startswith(t) for t in _PREFIX_TAGS):
        return ""
    return raw.strip()
```
